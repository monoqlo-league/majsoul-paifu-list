# 雀魂 牌譜スタッツ出力 リスト取得版

対局一覧のCSVに載っている雀魂の牌譜を、間隔をあけて順に取得し、和了・放銃・立直・副露の成績を集計のCSVにするChrome拡張機能。非公式。

「雀魂 牌譜スタッツ出力」(v0.10.0)を、対局一覧からの取得だけに絞った版。違いは3つ。

- **雀魂で牌譜を開いても取り込まない。** 取り込むのは、この拡張機能が対局一覧に沿って取得した牌譜だけ。
- **牌譜URLやゲームIDを打ち込む欄は無い。** 取得する対局は、対局一覧のCSVで決める。出力済みのCSV(以前に保存した集計のCSV)を読み込むと、そこに載っている対局は取得しない。
- 集計の内容と、CSVを保存するときに保存先を選ぶ画面が出る点は、元の版と同じ。

対局中の画面には何もしない。取得した内容はこのブラウザの中にだけ保存し、外部には送らない。

## 安全性について

この拡張機能がすること・しないことは次のとおり。ソースはすべてこのリポジトリにあり、誰でも読んで確かめられる。

| 項目 | 内容 | 確かめる場所 |
|---|---|---|
| 権限 | 「storage」と「downloads」の2つだけ。閲覧履歴、Cookie、ほかのタブの中身を読む権限は持たない | `manifest.json` の `permissions` |
| 動くサイト | 雀魂の4つのドメイン(`game.mahjongsoul.com` など)だけ。ほかのサイトでは動かない | `manifest.json` の `host_permissions` と `content_scripts` |
| 外部への送信 | しない。外部のサーバーへ送る処理(`fetch`、`XMLHttpRequest`、`sendBeacon` など)はコードに無い | `src/`、`popup/` |
| 雀魂への通信 | 雀魂が開いている接続に、牌譜の要求を1件ずつ、待機時間をあけて送るだけ。要求の形は、雀魂自身が牌譜を開くときと同じ | `src/hook.js`、`src/content.js` |
| ログイン情報 | ログイン時の通信から読むのは、雀魂のバージョン文字列だけ。ログイン情報は保存も送信もしない | `src/hook.js` の `onSend` |
| 保存するもの | 取得した対局の集計結果を、ブラウザの拡張機能用の保存領域に置く。外に出るのは、本人が「CSVを保存」したファイルだけ | `src/content.js`、`src/background.js` |
| 外から読み込むコード | 無い。外部のライブラリやCDNは使わず、`eval` のような文字列からコードを作る処理も無い | 全体 |

配布しているZIPは、このリポジトリのコミットをそのままZIPにしたもの。どのコミットから作ったかと、ZIPの指紋(SHA-256)は、配布ページに載せている。

拡張機能が悪さをしなくても、ログイン中のアカウントで雀魂に要求を送ることに変わりはない。アカウントへの影響が無いとは言い切れないので、サブアカウントでの利用を推奨する。

## 入れ方

1. zipを展開する。
2. Chromeで `chrome://extensions` を開き、右上の「デベロッパー モード」をオンにする。
3. 「パッケージ化されていない拡張機能を読み込む」を押し、展開したフォルダ(`manifest.json` があるフォルダ)を選ぶ。
4. 雀魂のタブを再読み込みする。

展開したフォルダは消さない。消すと拡張機能も消える。

元の「雀魂 牌譜スタッツ出力」とは別の拡張機能として入る。取得した対局の保存場所も別。両方を入れておくこともできるが、同時に取得を走らせない(雀魂への要求が2倍になる)。使わないほうは `chrome://extensions` でオフにしておくとよい。

使う権限は2つ。取得した対局を保存する「storage」と、CSVを保存するときに保存先を選ぶ画面を出す「downloads」。

## 使い方

1. 雀魂にログインしたタブを開いておく。
2. アイコンを押し、「対局一覧のCSVを読み込む」で、取得したい対局一覧のCSV(例: `202608-01.csv`)を選ぶ。「取得する一覧」に、その名前と対局数が出る。
3. 以前に保存した集計のCSVがあれば、「出力済みのCSVを読み込む」で選ぶ。そこに載っている対局は取得せず、行はそのまま次に保存する集計のCSVに書き込む。指定は「解除」を押すまで残る。
4. 「取得を始める」を押す。1件ごとに待機時間(既定は20秒)をあけて、順に取得する。ポップアップは閉じてよい。
5. 終わったら「CSVを保存」を押す。保存先とファイル名を選ぶ画面が出る。名前の初期値は、対局一覧の名前に `-summary` を付けたもの(`202608-01.csv` なら `202608-01-summary.csv`)。

ファイルを選ぶ画面でポップアップが閉じてしまう場合は、「広い画面で開く」から行う。CSVの文字コードはUTF-8とShift_JISのどちらでも読める。

### 対局一覧のCSV

雀魂の大会の対局記録CSVと同じ形のもの。「牌譜リンク」の列のゲームIDを読む。その見出しの列が無いCSVは、ファイル全体からゲームIDを拾う。

読み込んだ一覧は覚えていて、「対象」で選べる。対象に一覧を選ぶと、表とCSVはその一覧の対局だけになり、「取得する一覧」もそれに替わる。

| 対象 | 載る対局 | 保存するCSVの名前(初期値) |
|---|---|---|
| 対局一覧のCSV(例: `202608-01.csv`) | その一覧に載っている対局だけ | `202608-01-summary.csv` |
| すべての対局 | 拡張機能にある全対局と、出力済みのCSVの全対局 | `majsoul-summary.csv` |
| 個別の対局 | その1対局 | `majsoul-summary.csv` |

### 出力済みのCSV

- 読み込めるのは、この拡張機能(または元の版)で保存した集計のCSV(「ゲームID」「名前」「局数」の列があるもの)。
- 保存する集計のCSVには、出力済みのCSVの行が先頭に入り、続けて新しく取得した対局が入る。保存したCSVは、そのまま次回の出力済みのCSVとして使える。
- 同じ対局が拡張機能にも残っている場合は、二重にせず、拡張機能のデータから作った行を使う。
- 出力済みのCSVに無い列は空欄で引き継ぐ。

### 取得の動き方

- 1件目はすぐ取得し、以降は前の要求から待機時間をあけて1件ずつ取得する。止めて始め直しても、前の要求から待機時間がたつまでは送らない。
- 待機時間は「1件ごとの待機」の欄で決める。既定は20秒で、5〜600秒の範囲。範囲の外の値は、始めるときに範囲内へ直す。取得中は変えられない。最後に使った値は覚えている。
- 出力済みの対局と取得済みの対局は、雀魂に要求せず省略する。同じ一覧でもう一度「取得を始める」を押すと、まだ無い対局だけを取得する。
- 雀魂がエラーを返したとき(取得制限など)と、応答が無いときは、その場で全体を止める。以後の要求は送らない。エラーの番号は画面に出る。残りは「残りを再開」で続きから取得できる。
- 「止める」でいつでも止められる。順番待ちは雀魂のタブが進めるので、雀魂のタブを閉じたり再読み込みしたりすると止まる。「残りを再開」を押す。
- 雀魂のタブを裏に回したままにすると、ブラウザがタイマーを間引くため、間隔が待機時間より長く(最大1分ほどに)なることがある。短くなることはない。
- 牌譜の中身を読めなかった対局は、理由付きで一覧に出して次へ進む。3件続くと全体を止める。
- 雀魂のタブが接続できていない、またはバージョンを読み取れていないときは、要求を送らずに止まる。雀魂のタブを再読み込みしてログインし直す。それでも止まるときは、雀魂で牌譜を1件だけ手で開いてからやり直す(その牌譜は取り込まれないが、要求の形を覚える)。

注意:

- この拡張機能は、ログイン中のアカウントの接続を使って雀魂に要求を送る。間隔をあけるのは、短時間の大量アクセスと判断されるのを避けるため。待機時間を短くするほど、取得制限に当たりやすくなる。間隔をあけても、アカウントへのリスクが無いとは言えない。
- 要求の形は雀魂自身が牌譜を開くときに送るものと同じにしている。応答は雀魂の画面には渡さないので、画面は変わらない。

## 表

表は集計の1つだけ。1行が1対局の1人。

| 分類 | 列 |
|---|---|
| (共通) | ゲームID、名前、内部ID、局数、最大連荘数 |
| 和了 | 和了数、和了点合計、和了点平均、最高和了点、和了巡目合計、和了巡目平均、ツモ和了、ロン和了、ダマ和了、役満和了、ドラ、赤ドラ、裏ドラ |
| 放銃 | 放銃数、放銃点合計、放銃点平均、立直後放銃、宣言牌放銃 |
| 立直 | 立直数、立直巡目合計、立直巡目平均、立直和了、先制立直、追っかけ立直 |
| 副露 | 副露局数、副露和了、副露回数 |
| 役 | 役ごとに1列(60列)と「その他の役」 |

役の列は、雀魂が和了の役として記録するものすべて。値は、その役が付いた和了の回数。

- 通常の役: 門前清自摸和、立直、槍槓、嶺上開花、海底摸月、河底撈魚、役牌 白、役牌 發、役牌 中、役牌:自風牌、役牌:場風牌、断幺九、一盃口、平和、混全帯幺九、一気通貫、三色同順、ダブル立直、三色同刻、三槓子、対々和、三暗刻、小三元、混老頭、七対子、純全帯幺九、混一色、二盃口、清一色、一発
- 役満: 天和、地和、大三元、四暗刻、字一色、緑一色、清老頭、国士無双、小四喜、四槓子、九蓮宝燈、純正九蓮宝燈、四暗刻単騎、国士無双十三面待ち、大四喜
- 古役(大会のルールで有効にしたときだけ出る): 八連荘、燕返し、槓振り、十二落抬、五門斉、三連刻、一色三順、一筒摸月、九筒撈魚、人和、大車輪、大竹林、大数隣、石の上にも三年、大七星
- その他の役: 上のどれでもない役(イベント用の役など)の回数

ドラ・赤ドラ・裏ドラは役の列ではなく、和了の分類に枚数で出す。流し満貫は雀魂では流局として記録されるため、役の列には無い。

## 数え方

| 項目 | 定義 |
|---|---|
| 和了点・放銃点 | 手の点数。本場と供託は含まない |
| 巡目 | 立直は宣言牌が本人の何打目か。ツモ和了は本人の打牌数+1。ロン和了は放銃牌が放銃者の何打目か(槍槓は加槓した手番) |
| 放銃数 | 局単位。ダブロンは1回と数え、点数は両方を足す |
| 立直数 | 成立した立直だけ。宣言牌でロンされたものは「宣言牌放銃」に数える |
| 最大連荘数 | 親を続けた局数の最大。和了でも聴牌流局でも、次の局も親なら続いたと数える。親を3局続けたら 3、1局で流れたら 1、親番が一度も来なければ 0 |
| 最高和了点 | その対局でいちばん高かった和了点。和了が無ければ空欄 |
| 巡目の合計 | 和了巡目合計は和了ごとの巡目の合計、立直巡目合計は立直ごとの巡目の合計。複数の対局をまたいだ平均巡目は、合計を回数で割ると正確に出る |
| 先制・追っかけ | 他家の立直が成立していなければ先制、していれば追っかけ |
| 立直後放銃 | 自分の立直が成立した後の放銃。宣言牌での放銃は含まない |
| 副露 | チー・ポン・大明槓。暗槓・加槓・北抜きは数えない |
| 副露局数 | 1回以上副露した局の数 |
| 副露和了 | 副露した局での和了数 |
| ドラ・赤ドラ・裏ドラ | 和了時に役として付いた枚数。役満の和了では雀魂がドラを記録しないため 0 になる |
| 役の列 | その役が付いた和了の回数。役満の和了では役満の役だけを数える |
| ダマ和了 | 立直も副露もしていない和了 |
| 宣言牌放銃 | 立直の宣言牌でロンされた回数。立直数と立直後放銃には含めない |

雀魂牌譜検討サポーターの戦績出力とは、次の2点で数字が違うことがある。

- 放銃: あちらはダブロンを2回と数える。
- 立直: あちらは宣言牌でロンされた立直も数える。

## 制限

- 拡張機能を入れた後に、雀魂のタブを再読み込みしてから使う。
- 四人麻雀と三人麻雀の通常ルールが対象。血戦など特殊ルールの和了は集計されない。
- 責任払い(包)は考慮しない。放銃者だけを放銃として数える。
- 保存形式がごく古い牌譜は取得できない(その場合はポップアップに理由が出る)。
- 雀魂側の更新で牌譜の形式が変わると、動かなくなることがある。

## フォルダ構成

| 場所 | 中身 |
|---|---|
| `manifest.json` | 拡張機能の定義 |
| `src/hook.js` | 雀魂のページで、頼まれた牌譜の要求を1件送り、その応答だけを取り出す |
| `src/content.js` | 取得した牌譜を集計して保存する。取得の順番待ちと待機時間を管理する |
| `src/ids.js` | 読み込んだCSVからゲームIDを拾う |
| `src/pb.js` `src/schema.js` | 牌譜データ(protobuf)の読み取り |
| `src/analyze.js` | 和了・放銃・立直・副露の判定 |
| `src/tables.js` | 表の組み立てとTSV/CSVへの変換 |
| `src/fans.js` | 役の名前 |
| `src/background.js` | アイコンの数字。CSVの保存(保存先を選ぶ画面を出す) |
| `popup/` | ポップアップ画面 |
| `tools/` | `schema.js` と `fans.js` を作り直すスクリプトと元データ |
| `test/` | テストと、テスト用の牌譜データ。配布用のzipには含めない |

## 開発

```
npm test                 # 集計のテスト(test/ が必要。配布用のzipには入っていない)
NODE_PATH=<playwrightのあるnode_modules> npm run test:e2e   # 実ブラウザでの通し確認(待機時間を実時間で確かめるので2分ほどかかる)
npm run gen              # tools/liqi.json と tools/fan.json から src/schema.js と src/fans.js を作り直す
```

出力する項目を増やすときは、`tools/gen-assets.mjs` の `WANTED` に必要なフィールドを足して `npm run gen` を実行し、`src/analyze.js` と `src/tables.js` を書き換える。
